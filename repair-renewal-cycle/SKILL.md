# Repair Renewal Cycle

## R - 原文

> 蛊：元亨。利涉大川；先甲三日，后甲三日。

> 剥：不利有攸往。

> 复：不远复，无祗悔，元吉。

> 井：改邑不改井。

> 革：巳日乃孚。

> 鼎折足，覆公餗。

## I - 方法论骨架

《周易》里有一条很清楚的修复链：蛊是积弊要处理，剥是结构剥落不宜扩张，复是及时回到正轨，井是基础设施和公共资源要修，革是改革要等信任成熟，鼎是新秩序必须能承载，涣是涣散后重组，节是重组后设置边界。

这个 skill 帮用户判断：当前是积弊、剥落、复归、修井、改革、立新制，还是节制阶段。它的输出不是“冲一把”，而是修复顺序。

## A1 - 书中的应用

### 案例 1：蛊先处理旧账

- 问题：积弊已经形成。
- 文本动作：“先甲三日，后甲三日。”
- 方法论：改革前后都要留出清理、准备和复查。
- 结果：现实中修复旧系统不能只发布新口号。

### 案例 2：剥复的收与回

- 问题：基础正在剥落。
- 文本动作：剥“不利有攸往”，复“不远复”。
- 方法论：剥时收缩，能早回头就早回头。
- 结果：现实中应先止血、保种子、恢复基本循环。

### 案例 3：革鼎的改革承载

- 问题：旧制要革，新制要立。
- 文本动作：革“巳日乃孚”，鼎“鼎折足，覆公餗”。
- 方法论：改革要信任成熟，新制度要有承载结构。
- 结果：现实中不能只换名词，要检查流程、责任和资源。

## A2 - 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户面对长期积弊、组织病、技术债、旧项目烂尾。
2. 用户想知道现在该收缩、修复、改革还是新建。
3. 用户要做制度改革、流程重构、产品重写、团队重组。
4. 用户读到蛊、剥、复、井、革、鼎、涣、节。

### 语言信号

- “这是蛊卦那种旧账吗？”
- “现在该剥、复，还是革？”
- “我要重构一个系统，周易怎么判断先后？”
- “旧制度坏了，新制度怎么立得住？”
- “井卦的改邑不改井怎么用？”

### 与相邻 skill 的区别

- 与 `hexagram-situation-diagnosis` 的区别：本 skill 专门处理修复和更新流程。
- 与 `advance-retreat-boundary` 的区别：本 skill 判断修复顺序，后者判断具体进退。
- 与 `scale-and-restraint-control` 的区别：修复后仍需后者检查承载规模。

## E - 可执行步骤

1. **判断损坏类型**
   - 完成标准：区分积弊、剥落、偏离、基础设施失修、改革时机、承载不足、涣散无节。
2. **确定修复阶段**
   - 完成标准：标注当前处在蛊、剥、复、井、革、鼎、涣、节中的哪一段。
3. **排定先后**
   - 完成标准：给出先止血、清旧账、修基础、建立信任、改革、承载、设边界的顺序。
4. **设置复查点**
   - 完成标准：列出改革前和改革后必须检查的 3 个信号。

## B - 边界

### 不要在以下情况使用

- 用户只是短期心情不好，没有系统性损坏。
- 用户需要具体工程方案、法律方案或医疗方案。
- 用户想用周易给改革找神秘背书，而不提供事实。

### 失败模式

- 一看到问题就说改革，跳过止血和修井。
- 一味守旧，忽略革的必要性。
- 新制度没有承载结构，变成“鼎折足”。

### 来源边界

本 skill 使用经文中的修复和更新结构，不扩展到后世完整义理系统。
