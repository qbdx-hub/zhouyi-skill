# Scale And Restraint Control

## R - 原文

> 小过：可小事，不可大事。

> 大过：栋挠，利有攸往，亨。

> 小畜：亨。密云不雨。

> 大畜：利贞，不家食吉。

> 损：有孚，元吉，无咎。

> 益：利有攸往，利涉大川。

## I - 方法论骨架

《周易》不断区分大小、蓄积、过度、损益和节制。小过不是完全不能做，而是只可小事；大过不是普通压力，而是梁柱弯曲，需要结构性处理；小畜是蓄而未雨，大畜是更强的蓄养；损和益不是简单少和多，而是资源重新配置是否有孚、是否可承载。

这个 skill 用来检查“目标规模”和“承载能力”是否匹配，并把行动降级或升级到合适尺度。

## A1 - 书中的应用

### 案例 1：小过限制行动规模

- 问题：条件只能支撑小动作。
- 文本动作：“可小事，不可大事。”
- 方法论：不是不行动，而是把行动缩小。
- 结果：现实中用 MVP、试点、局部修复代替大承诺。

### 案例 2：大过提醒结构承载

- 问题：压力已经压到梁柱。
- 文本动作：“栋挠。”
- 方法论：不是再加努力，而是先处理承重结构。
- 结果：现实中遇到组织、现金流、系统容量过载，应先加固结构。

### 案例 3：损益检查资源配置

- 问题：增加和减少都可能正确，也可能错配。
- 文本动作：损“有孚，元吉”，益“利有攸往，利涉大川”。
- 方法论：资源调配要看信任、方向和承载。
- 结果：现实中裁剪、聚焦、加资源都必须说明条件。

## A2 - 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户想判断现在做小试点还是大投入。
2. 用户担心目标太大、资源太少、承诺太满。
3. 用户处理预算、团队、产品范围、学习计划、改革规模。
4. 用户读到小过、大过、小畜、大畜、损、益、节。

### 语言信号

- “这是小事能做，大事不能做吗？”
- “我是不是承诺太大了？”
- “现在该小畜还是大畜？”
- “损和益怎么用在资源配置？”
- “大过的栋挠是不是说明结构撑不住？”

### 与相邻 skill 的区别

- 与 `advance-retreat-boundary` 的区别：后者判断进退，本 skill 判断规模。
- 与 `humility-overreach-check` 的区别：后者处理高位过盛，本 skill 处理承载错配。
- 与 `repair-renewal-cycle` 的区别：后者处理修复顺序，本 skill 处理修复或扩张的尺度。

## E - 可执行步骤

1. **列出目标规模**
   - 完成标准：把用户行动分为小事、中事、大事或涉大川级别。
2. **列出承载资源**
   - 完成标准：检查时间、资金、团队、信任、制度、技术、注意力。
3. **判断尺度错配**
   - 完成标准：说明是小过、大过、小畜、大畜、损、益、节中的哪类问题。
4. **调整行动尺寸**
   - 完成标准：输出缩小试点、蓄积等待、加固结构、减少承诺、增加资源或设置节制。

## B - 边界

### 不要在以下情况使用

- 用户只问是否该行动，不涉及规模。
- 用户要精确财务预算但没有数据。
- 用户要求用周易替代项目管理、工程容量或法律评估。

### 失败模式

- 把“小过”说成完全不做。
- 把“大过”说成继续努力即可。
- 只看资源多少，不看信任和制度承载。

### 来源边界

本 skill 依据经文中的大小、蓄积、损益和节制结构，不延伸到完整预算模型。
